5. DATA PREPROCESSING AND LEAKAGE PREVENTION
--------------------------------------------
Inspect preprocessing carefully.

5.1 Data validation
Check:
- Missing values.
- Infinite values.
- Duplicate or invalid records.
- Incorrect column names.
- Invalid cycle ordering.
- Unexpected data types.
- Incorrect engine identifiers.
- Unexpected sensor distributions.
- Inconsistent feature sets between training and inference.

Do not automatically delete every unusual observation. An unusual sensor reading may be a data error or meaningful engine degradation. Choose rules based on evidence and document them.

5.2 Train/validation/test separation
Ensure preprocessing does not use held-out test data to fit the model.

Fit these operations on training data only:
- Feature scaling.
- Imputation.
- Data-driven feature selection.
- Other transformations that learn parameters from data.

Apply fitted transformations to validation and test data without refitting.

Where there are multiple observations per engine, verify that the split strategy matches the evaluation design. For engine-independent evaluation, engines in the training split should not also appear in the held-out split.

If a benchmark specifies predefined splits, respect them unless a documented experiment explicitly requires another strategy. Do not silently replace prescribed splits with random row-level splitting.

5.3 Sequence/window generation
If sliding windows are used, verify:
- Window length.
- Window stride.
- Feature order.
- Engine boundaries.
- Target alignment.
- Handling of engines shorter than the required window.
- Consistency between training and inference.

No window may contain observations from different engines. The target must match the intended prediction point. If a window covers cycles t-W+1 through t and predicts RUL at the final observation, its label must correspond to cycle t. Keep the policy consistent in training and inference.

5.4 Persist preprocessing
If the model requires scaling, imputation, or other learned transformations, save required preprocessing objects with the trained model. Inference must use the same feature order and transformations used during training.

Expected result: a reproducible preprocessing pipeline with tests and no known critical target leakage or alignment errors.

7. MODEL EVALUATION AND RESEARCH INTEGRITY
------------------------------------------
The project must demonstrate that predictions are evaluated correctly.

7.1 Required metrics

Mean Absolute Error:
    MAE = (1/N) * sum(abs(y_i - predicted_y_i))

Root Mean Squared Error:
    RMSE = sqrt((1/N) * sum((y_i - predicted_y_i)^2))

Here y_i is actual RUL, predicted_y_i is predicted RUL, and N is the number of evaluated observations. Express metrics in cycles when the RUL target is measured in cycles.

7.2 Metric correctness
Verify:
- Ground-truth and prediction arrays have matching shapes.
- Metrics use the intended evaluation split.
- Missing predictions are not silently discarded.
- Reported values correspond to the actual model and dataset.
- Training labels are not accidentally used as test labels.
- Evaluation is not performed only on training data.

If additional metrics exist, verify their definitions and implementations.

7.3 Benchmark comparison
If CruiseBench is used, consult the benchmark's documented evaluation protocol before comparing results. Previously encountered documentation reported results for multiple architectures under a specified window configuration, but those figures are not automatically comparable to this project's results.

Verify dataset version, train/test protocol, RUL definition, input features, window length/stride, evaluation procedure, and metric definition before comparison. Explain differences if these do not match.

A working application and a scientifically valid model are separate requirements. The app may start and display predictions while still having incorrect RUL labels, data leakage, or invalid evaluation.

The expected outcome is not merely "AeroShield runs on localhost." It is:

"AeroShield runs locally, its predictions come from a reproducibly trained model, its evaluation is methodologically sound, and its demonstrated capabilities are supported by test evidence."
